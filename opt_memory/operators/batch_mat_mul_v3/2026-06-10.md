### TQue DMA Double Buffering enables compute/memory overlap
- Category: memory_optimization
- Speedup: 3.3054x
- Using TQue with depth=2 allows overlapping data transfer with computation. While one tile is being computed, the next tile's data is being DMA'd in. This is essential for matmul-like kernels on Ascend NPU.

### fp32 UB accumulation eliminates precision loss
- Category: compute_optimization
- Speedup: 3.3054x
- Accumulating partial dot products in fp32 inside UB, then casting to fp16 at write-out, maintains numerical precision while keeping memory bandwidth efficient. Direct fp16 accumulation would cause significant precision loss.

### Release build (-O2) gives <1% gain for memory-bound scalar kernels
- Category: compiler_flags
- Switching Debug→Release without algorithmic change is ineffective. The bottleneck is global memory latency (~hundreds of cycles per access), not instruction scheduling. Fix the algorithm first, then tune compiler flags.

### Very small tiles (≤32) reduce DMA efficiency and increase overhead
- Category: tiling_strategy
- Tiles smaller than 64 elements increase DMA transaction count and TQue EnQue/DeQue overhead. Each DMA has fixed overhead — larger tiles amortize this. However, tiles must fit within UB capacity (typically ~192KB).

### Scalar GlobalTensor access is pathologically slow for matmul
- Category: architecture
- The baseline BMM kernel running on Ascend 910B4 with scalar GlobalTensor access is ~500-1000x slower than PyTorch's torch.matmul. Each element access goes through global memory with hundreds of cycles latency. Even a simple UB tiling with DMA can recover 3-4x of this gap. Full Cube-unit utilization would be needed for competitive performance.
